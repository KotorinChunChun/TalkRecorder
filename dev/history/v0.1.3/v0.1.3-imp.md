# v0.1.3 実装計画と検証

- [x] 同期出力で入力なし・同期未確定・同期済みを集計し、録音の画面、CLI、診断記録へ反映する。
- [x] 連続パケットの微小な時刻揺れを吸収し、欠損があれば250ミリ秒単位で保護する。解析プロセスへの要求は1トラックにつき最大1秒に1回とする。
- [x] 未判定の重複ログと、保存成功後の空のエンコーダーログを減らす。復旧用データと確定済み録音の扱いは既存の確定手順に従う。
- [x] 同期・編集・復旧の回帰検証と、隔離設定でのCLI録音を行う。

65時間18分の既存録音では、386本の保存後に `raw` と `processed` の作業用音声が回収されていた。空のエンコーダーログが386個あり、診断用JSONLは約109 MiBだった。空き容量が設定値に達すると通常停止し、長期保管する確定音声は利用者が管理する。

通常回帰テスト200件、実モデルVAD 3件、実エンコード4件、録音中のM4A分割確定1件が合格。隔離設定による24秒のCLI録音では、25ブロック中23ブロックが完全同期した。不完全なブロックは開始と停止の境界だけで、CLI・記録に入力未取得と同期未確定が区別されて出た。2本のM4Aが確定し、非発話のみの1区間を除外した。作業用音声と空のエンコーダーログは回収された。

本PCのKotorinToys管理下へv0.1.3の本体とCLIを配置した。初回はタイトルのない補助ウィンドウを拾う方法で非表示の判定ができず、いったん旧版へ戻した。設定画面のタイトルを条件にする既存の検証と同じ方法で再試行し、非表示起動、設定のハッシュ一致、既存録音フォルダーの保持を確認した。管理CLIで起動経路が `via_kotorintoys`、状態が「録音中」となり、稼働セッションで31ブロック中30ブロックが完全同期した。

RDP接続・切断の実操作と、修正版での複数日にわたる録音は未検証。
