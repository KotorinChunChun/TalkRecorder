# TalkRecorder v0.1.1 配布記録

Windows 11 x64向けのセットアップを追加し、KotorinToysの公開一覧から導入できるようにする。録音機能はv0.1.0と同じ。従来のZIP版もv0.1.0のリリースから入手できる。

Inno Setupでユーザー単位の登録を作り、既定の導入先は `%LOCALAPPDATA%\Programs\TalkRecorder` とする。上書き時の正常終了と削除時の自動起動予約の整理には、KotorinToysの共通保守補助を使う。インストーラーは導入先の `local` や `recordings` を削除対象に指定しない。ZIP版の別フォルダーにある設定と録音の場所は利用者が確認する。

## ビルド

1. `scripts/New-PortableRelease.ps1` の生成物を展開し、`tool.json` と共通保守補助の自己完結版（win-x64、.NET 10.0.15）を追加する。共通インストーラーと保守補助はKotorinToysコミット `5e8f3c7` のソースを使う。音声ランタイムとFFmpegは初回準備スクリプトで入手する。
2. `TalkRecorder.exe` と保守補助EXEを開発者証明書 `CN=KotorinChunChun` で署名する。Inno Setup 7で `packaging/talkrecorder-managed.iss` を指定する。共通定義の `ProductName`、`ProductAppId`、`ProductVersion`、`Payload`、`OutputDirectory` に加え、`CommonInstaller` に共通 `installers/product.iss` の絶対パス、`SignedOutput` に専用作業フォルダーを渡す。
3. Inno Setupの `developer` SignToolにSHA-256署名とRFC 3161タイムスタンプを設定する。署名済みセットアップを検証してから、最終ファイルのSHA-256で `TalkRecorder-SHA256SUMS.txt` と `TalkRecorder-packages.json` を生成する。

## 確認結果

- Rustの通常テストと配布ビルドが成功した。署名済みEXEを隔離設定で起動し、無表示・自動録音OFF・PID照合・管理画面表示・正常終了を確認した。
- 本体、保守補助、セットアップのAuthenticodeとRFC 3161タイムスタンプを確認した。コンパイラーのログでアンインストーラーの署名を確認した。署名後に配布入力442ファイルを検査し、秘密情報の検出は0件だった。
- 実機への正式導入と録音機器を使う試験は今回の確認に含めていない。

## 旧ローカル開発時の記録

公開版の準備前にローカル開発で同じ番号を使用した。当時確認した機能は [v0.1.0 初回公開版](../v0.1.0/v0.1.0-imp.md) に含まれる。以下は当時の実測である。

- [x] 管理契約2の状態確認、表示、正常終了を実装する。無表示起動と録音開始を分け、録音の設定初期値をOFFにする。
- [x] 隔離設定で無表示起動と、正しいPIDでの設定画面表示・正常終了を確認する。新規設定では録音しない。
- [x] このPCの既存機器・保存先で導入し、KotorinToys 経由のサインイン予約と実際の録音開始を確認する。

録音は `--startup --launch-origin via_kotorintoys` と端末の録音設定が揃った場合に開始する。通常の起動、手動の管理起動、破損した設定ではこの機能で録音を始めない。KotorinToys からの停止要求は、既存の録音停止と保存終了処理を通す。

通常の Rust テスト183件、リリースビルド、製品名とファイル版を確認した。配布候補EXEは、同一セッションでの隔離試験において無表示・録音OFF、誤ったPIDでの操作拒否、設定画面の表示、正常終了を確認した。

このPCには v0.1.1 をユーザー単位で導入した。既存の選択済みマイク1台とM4Aの保存設定を引き継ぎ、音声ランタイムの自己検査と空き容量照会を通した。設定変更はKotorinToysの既存共有タスクに追加し、タスクを手動実行して本体からの起動、管理窓口の「録音中」、新規セッション内への書き込みを確認した。実サインインによる発火は未確認。

公開一覧の管理能力を更新した。このPCの本体0.1.19は別製品の識別差により配信一覧を採用できなかったため、現在の参照ルートの一覧にも同じ定義を追加した。配布物と録音設定は公開一覧に含めない。本体のオンライン一覧試験は163件を確認した。

初回の常駐録音では、容量照会の結果が3秒更新されず、開始から約97秒で安全に停止した。取得済み音声はM4Aに確定した。常駐録音では稼働中の停滞判定を12秒にし、照会の失敗で停止した場合は保存完了後に新しい照会から再起動できるようにした。短時間に続けて失敗した場合の再試行は3回までとし、利用者の停止や実際の空き容量不足で再開しない。通常録音の停滞判定と録音開始前の照会期限は3秒のままにした。

修正版で通常テスト183件、リリースビルド、隔離した管理操作試験を再実施した。初回に確定したM4AはFFprobeでAAC・48kHz・約28秒と確認した。修正版を共有タスクから再起動し、同じセッションで252秒以上の取得と継続書き込み、管理窓口の「録音中」、設定画面の非表示を確認した。
