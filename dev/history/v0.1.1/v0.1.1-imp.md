# v0.1.1 KotorinToys 経由の常駐録音

この番号はローカル開発時の番号で、公開には使用しない。ここで確認した機能は [v0.1.0 初回公開版](../v0.1.0/v0.1.0-imp.md) に含める。

- [x] 管理契約2の状態確認、表示、正常終了を実装する。無表示起動と録音開始を分け、録音の設定初期値をOFFにする。
- [x] 隔離設定で無表示起動と、正しいPIDでの設定画面表示・正常終了を確認する。新規設定では録音しない。
- [x] このPCの既存機器・保存先で導入し、KotorinToys 経由のサインイン予約と実際の録音開始を確認する。

録音は `--startup --launch-origin via_kotorintoys` と端末の録音設定が揃った場合に開始する。通常の起動、手動の管理起動、破損した設定ではこの機能で録音を始めない。KotorinToys からの停止要求は、既存の録音停止と保存終了処理を通す。

通常の Rust テスト183件、リリースビルド、製品名とファイル版を確認した。配布候補EXEは、同一セッションでの隔離試験において無表示・録音OFF、誤ったPIDでの操作拒否、設定画面の表示、正常終了を確認した。

このPCには v0.1.1 をユーザー単位で導入した。既存の選択済みマイク1台とM4Aの保存設定を引き継ぎ、音声ランタイムの自己検査と空き容量照会を通した。設定変更はKotorinToysの既存共有タスクに追加し、タスクを手動実行して本体からの起動、管理窓口の「録音中」、新規セッション内への書き込みを確認した。実サインインによる発火は未確認。

公開一覧の管理能力を更新した。このPCの本体0.1.19は別製品の識別差により配信一覧を採用できなかったため、現在の参照ルートの一覧にも同じ定義を追加した。配布物と録音設定は公開一覧に含めない。本体のオンライン一覧試験は163件を確認した。

初回の常駐録音では、容量照会の結果が3秒更新されず、開始から約97秒で安全に停止した。取得済み音声はM4Aに確定した。常駐録音では稼働中の停滞判定を12秒にし、照会の失敗で停止した場合は保存完了後に新しい照会から再起動できるようにした。短時間に続けて失敗した場合の再試行は3回までとし、利用者の停止や実際の空き容量不足で再開しない。通常録音の停滞判定と録音開始前の照会期限は3秒のままにした。

修正版で通常テスト183件、リリースビルド、隔離した管理操作試験を再実施した。初回に確定したM4AはFFprobeでAAC・48kHz・約28秒と確認した。修正版を共有タスクから再起動し、同じセッションで252秒以上の取得と継続書き込み、管理窓口の「録音中」、設定画面の非表示を確認した。
