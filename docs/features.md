# TalkRecorder 機能一覧

適用版：v0.1.0

TalkRecorderは、Windows 11で人間の会話を複数の音声デバイスから録音するRust製デスクトップアプリです。マイクだけでなく、選択したスピーカー・ヘッドホンなどの出力デバイスで再生される会話も対象にします。全有効トラックへ同じ編集位置を適用し、対応するファイルを同じ長さで保存します。

操作方法は[利用ガイド](user-guide.md)を参照してください。

## 動作環境と構成

| 項目 | 現在の構成 |
| --- | --- |
| 対象OS | Windows 11、x64版EXE |
| 録音 | WASAPI共有モード。入力デバイスの取得と出力デバイスのループバック取得 |
| アプリ | Rust、eguiによる設定画面とタスクトレイ |
| 会話判定 | speech.cpp経由のSilero VADを標準使用 |
| 任意処理 | Haas日本語音声認識、RNNoise・DeepFilterNet3・NVIDIA NemotronLabs RE-USEのノイズ除去プラグイン |
| 保存用処理 | FFmpeg。WAVは直接書き込み、圧縮形式は外部プロセスで生成 |
| 処理場所 | 録音・会話判定・任意認識・ノイズ除去はローカル処理。準備スクリプトのダウンロードにはネット接続が必要 |
| ランタイム | 準備スクリプトはspeech.cppのVulkan版を使用。GPUドライバーのVulkan loaderが必要 |

アプリの実行にRust開発環境は不要です。ソースをビルドする場合はRust 1.89以上を使用します。端末別の最低CPU・メモリー・GPU仕様や、別PC向けの一式配布は未確定です。

## 実装済みの機能

| 分野 | 機能と動作 |
| --- | --- |
| 対象選択 | マイク2枠・スピーカー2枠。使う枠だけ有効にし、最大4台を選択。同一デバイスの重複指定は拒否 |
| 同時録音 | 有効デバイスを並列取得し、48kHzの共通時間軸へ整列。トラックごとに個別ファイルを生成 |
| 出力音の取得 | 選択した出力デバイスの再生音を取得。アプリ別の選択ではなくデバイス単位 |
| 同期 | デバイス時刻とサンプル位置から配置し、時間差・レート差を補正。全トラックへ同じカット・分割を適用 |
| 異常時計 | リモートマイク等の異常時刻を、device frameと受信時計から約5秒で学習。安定時だけ補正時刻を会話判定に使用 |
| 会話判定 | 発話・非発話・判定不能を区別。いずれかに発話があれば保持し、全台が非発話の場合だけ短縮 |
| 任意ノイズ除去 | 全枠OFF初期値。EXE配下に定義・DLL・必要資源が揃う方式だけを表示し、枠ごとに1方式を選択。選択時だけロードし、録音前に生成無音で妥当性・応答期限を確認 |
| 無音カット | 共通非発話を既定で合計3秒に短縮。先頭と末尾を残し、中央をカット |
| 分割 | 元の録音時間で既定600秒を目安に全トラックを分割。発話・未判定が続いても既定610秒で区切る |
| 会話なし除外 | 対象セグメントの全域が共通非発話で、既定600秒以上の場合に公開ファイル一式を残さない |
| 保存形式 | M4A / AAC、Opus、FLAC、WAV。標準はM4A |
| WAV容量削減 | 停止済みセッションの確定WAVをM4Aへ変換。全トラックを検査し、確定記録を切り替えてから元WAVを削除 |
| 継続保存 | 分割待ち中も内部確定を実行。区切った音声をバックグラウンドで順次書き出し、処理済み原音を解放 |
| 再接続 | 同じデバイスIDへ自動再接続。切断中も他のデバイスの録音を継続 |
| 復旧 | 起動時・録音開始前に未完了セッションを確認。内部確定済み音声と未確定末尾を復旧 |
| 解析異常 | 解析の応答期限と処理待ち上限を監視。判定不能として保持し、解析プロセスの再準備を試行 |
| 電源 | 録音中の自動スリープを抑止可能。強制スリープ等からの復帰後は別セッションで録音再開 |
| 画面 | 波形、会話・時計の状態、録音・編集後・解析待ちの時間、書き出し中・保存待ち・保存済みの区間を表示 |
| トレイ | 「トレイへ」または×で隠す。左ダブルクリック・右クリック「設定を開く」で復帰。右クリック「終了」で停止・保存を待って終了 |
| 多重起動防止 | 同一WindowsログオンセッションのGUIは1つ。再起動操作で既存画面を表示。EXE配置先・版・設定ファイルに依存しない。制限導入前の旧版は対象外 |
| デバイス記憶 | 選択・有効枠・名前を自動保存し次回起動へ復元。未接続でもIDを保持。同名の別機器へ自動切替しない |
| トレイの状態 | 待機と録音前の入力確認は青、録音は赤、準備・保存・復旧は橙、異常は黄色。非表示でも250msごとに確認し変化時だけ更新 |
| 設定保存 | 保存先・時間・音声処理等は「設定を保存」でJSONへ保存。読込失敗した設定は自動上書きしない |
| 容量による自動停止 | 保存先のユーザー可用量を約1秒間隔で監視。1024MB以下で通常停止、変更可能、0は無効。開始前にも確認。通知は出さず理由を画面とtimelineへ記録 |

## 会話判定と編集の条件

ここでいう「非発話」は音量ゼロではなく、VADが人間の会話を含まないと判定した状態です。環境音があっても非発話になる場合があり、機械音などを会話と誤判定する場合もあります。

| 有効トラックの状態 | 共通の扱い |
| --- | --- |
| 1台以上が発話 | 保持 |
| 発話がなく、1台以上が未判定 | 判定不能として保持 |
| 全台が非発話 | 共通非発話として短縮・分割・会話なし除外の対象 |

切断、時刻補正の学習中、欠損、解析失敗、未処理を非発話の根拠にしません。取得できなかった音声そのものを復元する機能はなく、欠損箇所の時間を維持して残します。

### 600秒・10秒・3秒の関係

分割間隔と分割用の非発話は、カット前の録音時間で判断します。次の分割間隔も直前の分割位置から数えます。発話・未判定を含む区間では、分割間隔に達した後、共通非発話の設定秒数（上限10秒）まで分割位置を待ちます。この時間を過ぎたら、発話中や未判定でも全トラックを同じ位置で区切ります。

| 既定設定での例 | 分割位置 |
| --- | --- |
| 580秒から全台で非発話が継続 | 600秒。基準到達時点で非発話10秒以上が既に成立 |
| 598秒から全台で非発話が継続 | 608秒 |
| 600秒を過ぎても会話や判定不能が継続 | 610秒。会話・未判定の音声を両区間に欠落なく振り分ける |

共通非発話の保持3秒は、原則として先頭約1.5秒と末尾約1.5秒へ配分します。分割位置を跨ぐ連続非発話に、3秒の保持枠を重ねて与えません。VADへの入力は最大1秒です。同期できなかったフレームを含む250ミリ秒の窓は保持し、同じ秒の残りは発話判定に従って編集します。

全会話なしの除外はセグメント全体の条件です。共通非発話だけの区間は、除外判定時間に達してから分割できます。途中に発話や判定不能が含まれれば、そのセグメントは自動除外しません。停止時の全非発話の末尾が除外判定時間より短ければ、3秒等へ短縮された短いファイルが残ることがあります。

## 音声処理のオプション

| 処理 | 適用範囲 | 初期状態 | 動作と制限 |
| --- | --- | --- | --- |
| Silero VAD | 全有効トラック | 有効 | 標準の会話判定。モデルを読み込めない場合は録音開始エラー |
| Haas 補助認識 | 全体設定 | 無効 | VADに加えて認識結果を補助利用。認識文・時刻情報を記録。空の認識結果だけを削除理由にしない |
| RNNoise | デバイス枠ごと | ノイズ除去なし | Rust実装、モデル内蔵の任意DLL |
| DeepFilterNet3 | デバイス枠ごと | ノイズ除去なし | Rust／tractの任意DLLと公式モデル。先読み等の30msを補償 |
| RE-USE | デバイス枠ごと | ノイズ除去なし | NemotronLabs RE-USEモデルで処理した音声を保存 |
| RE-USE laughter | デバイス枠ごと | ノイズ除去なし | 笑い声を残すモデルを選択 |

Haasとノイズ除去は独立して選択できます。ノイズ除去はEXE配下の必要一式だけを候補にし、プロジェクト直下の旧モデルパスだけでは有効にしません。既存のReuse／ReuseLaughter設定は対応プラグインIDとして読み取ります。配置しただけでは動作せず、入力確認も原音のままです。プラグインの開始前確認に失敗した場合はエラーを表示します。

ノイズ除去は有限の過去文脈を使う区間処理で、ステレオの左右を個別処理します。公式の連続APIと同じ音質を保証するものではありません。元音声を別ファイルへ恒久保存する機能はありません。応答期限を超える場合は、軽い方式またはノイズ除去なしを選択してください。

## 保存形式と一時領域

| 形式 | 現在の出力 | 特徴 |
| --- | --- | --- |
| M4A / AAC | AAC-LC、48kHz、モノラル64kbps／ステレオ128kbps | 標準形式。非可逆圧縮 |
| Opus | `.opus`、48kHz、モノラル64kbps／ステレオ128kbps | 非可逆圧縮 |
| FLAC | 48kHz、24bit系の内部音声を使用 | 内部の24bit整数音声に対して可逆。取得float32からの量子化は伴う |
| WAV | float32、RF64対応 | 非圧縮。WAV自動圧縮を無効にした場合にWAVを残す |

「WAV自動圧縮」が有効なら、保存形式でWAVを選んでも新規録音はM4Aになります。既存WAVの変換対象はTalkRecorderの保存先にある停止済み・確定済みの一式と復旧済み音声です。稼働中、形式不明、変換失敗、容量削減にならない短い音声は元WAVを保持します。変換には元WAVと変換先の一時容量が必要です。

内部確定は既定10秒間隔です。圧縮形式は内部FLAC、WAVはfloat32 RF64を使用し、公開ファイルの結合完了後に内部音声を解放します。「未処理音声の上限」の既定4,096MBは未処理・未確定の作業量に対する上限で、録音全体の累積容量の上限ではありません。ディスク空き不足・書込み失敗・回復不能な処理異常では停止してエラーを表示します。

「停止する空き容量」は初期1024MB（1MB＝1,048,576 bytes）、0で無効です。実際の保存先のボリュームを別workerで調べ、容量照会の遅延で取得処理を待たせません。取得前は新しい測定を待ち、録音中は非同期結果だけを読みます。照会失敗・3秒停滞も保存停止の根拠とします。入力確認は対象外です。現在録音のfinalizeを必ず試み、容量停止後の過去WAV追加変換はしません。容量予約ではなく、不足時は既存journal保持・復旧へ引き継ぎます。

## 保存フォルダーの内容

既定の保存先はプロジェクト基準フォルダーの `recordings` です。録音開始ごとに日時等を含むセッションフォルダーを作ります。

```text
recordings/
  device-formats.json     過去に取得したデバイス形式
  日時等を含むセッション名/
    session.json
    timeline.jsonl
    capture-timing.jsonl
    000001_track1.m4a
    000001_track2.m4a
    000001.complete.json
    raw/          処理待ち・復旧用の一時原音
    processed/    未確定の処理済み音声
    journal/      内部確定と公開ファイル生成用の記録
    recovered/    異常終了した未確定末尾の復旧結果
```

`raw`・`processed`・`journal`・`recovered`は状態や復旧の有無に応じて存在します。形式選択によって拡張子は変わります。Haasを有効にした場合の認識情報は記録ファイルに含まれ、字幕ファイルを自動生成する機能はありません。

| ファイル | 役割 |
| --- | --- |
| `000001_trackN.*` | 同じ番号が同じ編集区間のデバイス別音声 |
| `000001.complete.json` | 全トラック一式の確定記録。対応する記録がない一式は正常完了扱いにしない |
| `session.json` | アプリ版、設定、実際のデバイス・取得形式・枠の対応 |
| `timeline.jsonl` | 元時間とKeep／Cut／Splitの対応、解析状態、認識情報、完了・異常の記録 |
| `capture-timing.jsonl` | デバイス時計の補正モードと計測値。デバイスの切断・復帰を観測した時刻 |
| `session.lock`等 | 実行中セッションの保護用。ファイルの存在だけでは現在稼働中かを判定できない |

保存先のルートに `talkrecorder-audit.sqlite3` を作成します。保存または除外の結果は区間ごと、未判定・未取得・作業ファイルの回収は約1分ごとと停止時に記録します。未取得と同期未確定のフレーム数はトラック別の合計です。全区間を無音で除外した場合は区間全体を除外時間とし、無音カット時間との重複を避けます。日付は確定結果や回収を記録した時点で集計します。DBに問題があると画面と録音CLIに警告を出します。

分析用明細はローカル日付の当日と直前7日分を保持します。それより古い日の集計保存と明細削除は同じトランザクションで実行します。集計対象はv0.1.4以降に運転時に記録した分析イベントです。復旧用の各セッションの記録は、それぞれの保存処理で管理します。

`trackN`は有効にした枠だけを選択順に詰めた番号です。マイク1とスピーカー1を使う場合、通常 `track1` がマイク1、`track2` がスピーカー1です。4枠の固定番号や機器名ではないため、確実な対応は `session.json` で確認します。

通常保存は入力フレーム数の一致と各エンコーダーの正常終了後に一式を確定します。すべての通常録音を毎回実復号して検査する実装ではありません。既存WAVからM4Aへの容量削減時は、実復号も検証してから元WAVを削除します。

## 再接続と復旧

同じIDの機器が戻れば再接続を試みます。過去の取得形式が保存されている機器は、未接続の状態でも録音開始が可能です。初めて使う機器は接続してから選択します。チャンネル数が変わった場合は元の形式へ戻るまで待機します。別IDになった機器への自動置換は行いません。

起動時自動復旧が有効な場合、起動時と録音開始前に未完了セッションを確認します。確定済み内部音声は公開ファイルへ、未確定末尾は `recovered` へ同尺WAV一式として復旧し、自動圧縮が有効ならM4Aへ変換します。繰り返しの復旧で同じ区間を二重出力しないように管理します。稼働中セッションは除外し、復旧に失敗した原音は保持します。

録音中のスリープ抑止はアプリの実行中だけ有効で、Windowsの永続設定を変更しません。OSがスリープ・休止・電源断している間の音声は取得できません。復帰後は新しいセッションで再開し、休止時間全体を無音データとして生成しません。

検証結果と測定条件は[開発履歴](../dev/history/v0.1.0/v0.1.0-imp.md)に記録しています。

## 未実装と実機確認が残る項目

| 区分 | 項目 |
| --- | --- |
| 未実装 | 元音声の恒久併存保存、削除保留期間、波形への発話区間の重ね表示 |
| 未実装 | 日時指定の録音予約、アプリ内の録音ファイル一覧・再生・再編集、Haas結果からの字幕ファイル出力 |
| 実機確認が必要 | 4物理デバイスの同時同期精度、実際の抜き差し・強制スリープ、24時間以上の連続運転 |
| 品質評価が必要 | 多様な会話・雑音・同時話者でのVAD取りこぼし、Haas認識精度、ノイズ除去後の会話品質 |
| 環境ごとの確認が必要 | RDPの固定転送遅延、別PCでの音声ランタイム動作、他プレーヤーのAAC開始・終了時刻の扱い |

継続録音の構造は実装していますが、任意の環境で無期限に録音できる保証はありません。ディスク容量とOSの稼働状態に依存します。
