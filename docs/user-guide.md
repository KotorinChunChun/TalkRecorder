# TalkRecorder ユーザー説明書

適用版：v0.1.2

マイクとスピーカーの会話を同時に録音し、共通の非発話部分を短くして、デバイスごとの音声ファイルへ保存するアプリです。まずはM4A・標準の会話判定で使用できます。文字起こしを有効にする必要はありません。

機能の詳しい範囲は[機能一覧](features.md)を参照してください。

## 1. 起動する

準備済みの TalkRecorder.exe を開きます。

TalkRecorderをKotorinToysから導入した場合は、「保存・時間」の「KotorinToys 経由の自動録音」を有効にして設定を保存し、KotorinToysの自動起動設定で「KotorinToys経由」を選べます。通知領域のアイコンから録音状態と設定画面を確認できます。

起動すると設定画面が開きます。自動復旧中は「未完了録音を確認中」と表示され、終了するまで録音を開始できません。

同じWindowsログオンセッション内でGUIを1つだけ起動します。EXEを再び開いた場合は、起動済みの設定画面を表示して新しいプロセスを終了します。別の配置先・設定ファイルでもGUIは増やしません。音声解析用の子プロセスは別に表示される場合がありますが、追加のGUIではありません。

標準のフォルダー構成では、音声ランタイムは `runtime`、設定は `local\settings.json`、既定の録音先は `recordings` にあります。EXEだけを別の場所へ移すと、ランタイムや設定を見つけられなくなることがあります。

音声ランタイムや FFmpeg の導入については、[開発ガイド](development.md)を参照してください。

## 2. 録音するデバイスを選ぶ

1. 「デバイス」を開きます。
2. 使用する枠のチェックを入れ、一覧から実際の機器を選びます。
3. 使用しない枠はチェックを外します。
4. ノイズ除去は、最初は「ノイズ除去なし」にします。

| 枠 | 選ぶ機器 |
| --- | --- |
| マイク1・マイク2 | 会話を入力するマイク、ヘッドセットのマイクなど |
| スピーカー1・スピーカー2 | 会話を再生しているスピーカー、ヘッドホンなどの出力デバイス |

マイク1とスピーカー1だけの2台でも使用できます。初回はマイク1のチェックだけが入っていますが、実際の機器は選ばれていません。同じ機器を複数の有効枠へ重複指定できません。

スピーカー枠は、その出力デバイスで再生される音を直接取得します。再生音が物理的にマイクへ聞こえなくても録音できます。会議アプリ等が別の出力先を使っている場合は、その出力先を選んでください。アプリ別に音を分離する機能はありません。

選んだ機器と有効・無効は自動保存します。次回起動時に復元し、接続されていない機器は「未接続: 名前」と表示します。以前のIDを保持するため、同名の別機器へ切り替わることはありません。機器を接続し直した場合は、停止中に「デバイスを再取得」を押して一覧を更新できます。

自動保存に失敗した場合は、画面下部にエラーが残ります。保存先の状態を確認して「設定を保存」を押してください。読み込みに失敗した設定は自動保存で上書きしません。

## 3. 保存先と時間を設定する

「保存・時間」で保存先と形式を選びます。通常は次の初期値を使用できます。

| 項目 | 初期値 | 意味 |
| --- | ---: | --- |
| 保存先 | `recordings` | 基準フォルダー内に保存 |
| 保存形式 | M4A / AAC | 圧縮した音声をデバイス別に保存 |
| WAV自動圧縮 | ON | 新規のWAV指定はM4A保存へ変更。既存の確定WAVも変換後に削除 |
| 停止する空き容量 | 1024MB | 保存先の空きがこの値以下で自動停止。0は無効 |
| 分割間隔 | 600秒 | 元の録音時間で10分ごとを目安に区切る。共通非発話を待つのはその後最大10秒 |
| 分割用の共通非発話 | 10秒 | 全台が同時に非発話になっている必要時間 |
| 非発話を残す長さ | 3秒 | 連続する共通非発話を合計3秒まで残す |
| 会話なし除外の判定 | 600秒 | セグメント全体に会話も判定不能もない場合の除外判定時間 |

保存先はパスを直接入力するか、「選択」→フォルダーを開く／「上へ」→「このフォルダーを選択」で指定します。別ドライブや新しいフォルダーを指定する場合は、保存先欄へ絶対パスを入力できます。例：`D:\TalkRecorder\recordings`。

時間・保存形式・ノイズ除去などの変更は「設定を保存」を押し、「設定を保存しました」と表示されることを確認します。変更内容はその回の録音には保存前でも使われますが、次回起動へ残すにはこの操作が必要です。デバイスの選択・有効無効・名前だけは別途自動保存され、他の未保存変更を一緒に確定しません。

「停止する空き容量」はMB単位です（1MB＝1,048,576 bytes）。設定値以下なら録音開始を拒否し、録音中に到達した場合は取得を止めて、末尾データ・解析・圧縮・全トラックの確定を進めます。停止理由は画面と管理記録に残し、容量不足の事前通知や通知音は出しません。入力確認は容量停止の対象外です。

空き容量は約1秒間隔で、保存先の実ボリュームと実行ユーザーの可用量を調べます。未作成の保存先では実在する親を確認します。照会に失敗した場合や結果の更新が一定時間止まった場合は、取得済み音声を保存して停止します。停滞の判定は通常録音で3秒、KotorinToys経由の自動録音で12秒です。自動録音では、一時的な照会失敗で停止したあと、再度空き容量を確認できた場合に録音を再開します。設定値以下の空き容量で停止した場合は、保存先を確認してから再開してください。

この設定は保存用の容量予約ではありません。他アプリの急な容量消費などで保存に失敗した場合は、内部音声を保持して次回の復旧へ引き継ぎます。

## 4. 入力の波形を確認する

1. 「デバイス」を開き、使う機器を選んで有効にします。入力確認が自動で始まります。
2. マイクへ話し、該当枠の波形が動くことを確認します。
3. 録音したい会話を出力先で再生し、スピーカー枠の波形が動くことを確認します。
4. デバイス画面を離れるか、設定画面を隠すと入力確認が終わります。

入力確認では音声ファイルを保存せず、VAD・文字起こし・ノイズ除去も実行しません。波形だけの確認です。発話判定や時計補正の表示は、次の本録音で確認します。

入力確認中も機器と設定を変更できます。録音中や復旧中は処理が完了してから編集します。

## 5. 録音を開始する

「録音開始」を押します。「音声モデルを準備中」の後、画面上部に赤い印と「録音中」が表示され、波形が明るくなります。会話判定とファイルへの保存は録音中に行われます。

### 状態の見方

| 表示 | 意味 |
| --- | --- |
| 発話 | 人間の会話を含むと判定。保持する対象 |
| 非発話 | 会話を含まないと判定。全有効デバイスがこの状態なら共通カット等の対象 |
| 未判定 | まだ確定できない、欠損している、解析できない等。カットせず保持 |
| 時計を補正中 | 異常なデバイス時計を学習中。通常は約5秒を必要とする |
| 時計補正済み | 受信側の共通時間軸への補正が安定 |
| 時刻不安定・音声保持 | 時計が不安定なため、その音声を判定不能として保持 |

正常なデバイス時計では補正ラベルを表示しません。補正が終わらない場合も、未判定を無音と見なして削除することはありません。「時計補正済み」は機器やネットワークの固定遅延がゼロという意味ではありません。

画面下部の時間はそれぞれ異なります。

| 表示 | 意味 |
| --- | --- |
| 録音 | 元の取得時間。分割時間の基準 |
| 編集後 | 共通カット後の保持対象の長さ |
| 解析待ち | 取得済みで解析待ちの音声の長さ |

その下に、処理中の区間番号と工程（保存準備・書き出し・確定と検証）、保存待ち・保存済みの区間数、保存先のフォルダーを表示します。「解析待ち」が0秒になっても、音声ファイルの書き出しや検証が続くことがあります。停止後は取り込み、残りの解析、音声ファイルの保存の順に状態を表示し、最後に保存完了またはエラーを表示します。

## 6. トレイへ隠す

「トレイへ」、またはウィンドウ右上の×を押すと設定画面が隠れます。録音中ならそのまま録音を続けます。

画面へ戻るには、通知領域のTalkRecorderアイコンを左ダブルクリックするか、右クリックして「設定を開く」を選びます。アイコンが見当たらない場合は、Windowsの通知領域で隠れているアイコンを確認してください。EXEを再び開く方法でも起動済みの画面へ戻れます。

終了するには、通知領域アイコンを右クリックして「終了」を選ぶか、設定画面の「終了」を押します。録音中は停止・残りの解析・保存完了を待ってから終了します。復旧や圧縮の実行中も完了を待ちます。保存待ち中の×で処理を飛ばして終了することはありません。

起動直後は設定画面を表示します。トレイを作成できなかった場合は隠れず、画面にメッセージを表示します。

| 状態 | 色・形 |
| --- | --- |
| 待機 | 青い輪 |
| 録音 | 赤い丸 |
| 準備・保存・復旧 | 橙。処理別に形を区別 |
| 異常停止 | 黄色の印。設定画面で理由を確認 |

画面を隠していても、約250msごとに状態を確認して変化時だけアイコンと説明文を更新します。

## 7. 停止して保存結果を確認する

1. トレイに隠している場合は設定画面へ戻します。
2. 「停止」を押します。
3. 残りの解析・圧縮・ファイル確定を待ちます。処理中にアプリを強制終了しないでください。
4. 「録音開始」「設定を保存」が再び操作可能になったことと、画面下部の完了・エラーメッセージを確認します。
5. 表示されていた保存フォルダーをエクスプローラーで開きます。

「終了」を押した場合も、録音停止を要求して処理完了を待ち、アプリを終了します。

### ファイルの対応

マイク1とスピーカー1を使った場合の例です。

```text
recordings/
  日時等を含むセッション名/
    000001_track1.m4a      マイク1の最初の区間
    000001_track2.m4a      スピーカー1の同じ区間
    000001.complete.json  その一式の確定記録
    session.json          機器・設定・ファイル番号の対応情報
    timeline.jsonl        元時間とカット・分割等の記録
```

`000002`以降も、同じ番号のトラックを一緒に扱います。`trackN`は有効デバイスを順に詰めた番号で、4枠の固定番号ではありません。確実な機器との対応は `session.json` に記録されます。

対応する `.complete.json` がある一式を確定済みとして扱います。ファイルが見えたことだけでは全トラックの保存完了を判断できません。エラーが表示された場合や `.partial`・未完了データが残る場合は、セッションフォルダー全体を残して復旧を試してください。

音声ファイルは外部のプレーヤーで開きます。現在のアプリ内に録音一覧・再生・編集機能はありません。録音中・復旧中の `raw` や `journal` を削除すると、未確定部分を復旧できなくなります。

バックアップは停止・確定後に、音声だけでなく `.complete.json` と `session.json` を含むセッションフォルダー単位でコピーすると、機器の対応と完了記録も残せます。

## 8. 無音カットと分割の動作

このアプリでいう無音は、VADが判定する「会話がない状態」です。音量がゼロかどうかだけでは判断しません。

- いずれかのデバイスに会話があれば、全デバイス分の対応音声を残します。
- 全デバイスが同時に非発話なら、その連続区間を既定3秒までに短縮します。先頭と末尾へ約1.5秒ずつを残します。
- 1台でも未判定なら、その時間をカットしません。
- カット位置と分割位置は全デバイス共通です。機器ごとに別々の無音カットを行いません。

### 録音中の定期分割と保存

発話または未判定を含む区間は、既定で元の録音時間が10分に達した時点から、共通非発話の条件が成立した位置で分割します。待つのは「分割用の共通非発話」に設定した秒数まで（上限10秒）です。期限までに条件が成立しなくても、その位置で音声を残して区切ります。区切った音声は録音を続けながら書き出し、停止時には末尾と保存待ちの区間を処理します。

| 例 | 動作 |
| --- | --- |
| 9分40秒から全台で非発話が続く | 10分の時点で分割。追加で10秒待つ必要はない |
| 9分58秒から全台で非発話が続く | 共通非発話が10秒に達する10分08秒で分割 |
| 会話や未判定が続く | 10分10秒で分割。該当する音声は全トラックで保持 |

分割間隔は短縮前の録音時間で数えます。連続する同じ非発話が分割位置を跨いでも、3秒の保持枠は増えません。

### 会話がないのに短いファイルが残る場合

区間全体が共通非発話の場合は、除外条件を判定できる長さ（既定600秒）まで分割を待ちます。区間全体が非発話と確定し、既定600秒以上あれば自動で除外します。600秒未満で停止した末尾は、短縮したファイルが残ることがあります。

## 9. 保存形式と容量を調整する

| 形式 | 特徴 |
| --- | --- |
| M4A / AAC | 標準。AAC-LCの非可逆圧縮。48kHz、モノラル64kbps／ステレオ128kbps |
| Opus | 会話用の非可逆圧縮。対応プレーヤーで再生 |
| FLAC | 内部の24bit整数音声に対する可逆圧縮。取得float32からの量子化は伴う |
| WAV | 非圧縮float32。容量が大きい |

WAVを残すには「WAV自動圧縮」をOFFにします。ONのままWAVを選ぶと、新規録音はM4Aになります。既存の停止済みWAVは、全トラックをM4Aへ変換・検証できた後で元WAVを削除します。失敗したWAVや、変換しても小さくならない短いWAVは残します。

長時間録音では公開ファイルへの分割とは別に、既定10秒ごとに内部確定を行います。「未処理音声の上限」の4,096MBは未処理・未確定部分の上限で、累積録音4GBで必ず停止する設定ではありません。ただし実際の空き容量が不足すれば停止します。保存時間が長くなるほど公開ファイルの容量も増えます。

## 10. 音声処理を変更する

変更は停止後に行い、「設定を保存」を押します。機能を有効にする前に、必要なモデルを用意してください。

### 標準のVAD

「音声処理」のSilero VADを使って会話を判定します。Haasは不要です。小さい声が残りにくい場合は、発話しきい値や発話の前後の余裕を調整し、短い録音で結果を確認します。値を変更しても判定品質を保証するものではありません。

| 項目 | 初期値 | 保存・開始時に有効な範囲 |
| --- | ---: | --- |
| 発話しきい値 | 0.5 | 0.01〜0.99 |
| 発話前の余裕 | 0.3秒 | 0〜5秒 |
| 発話後の余裕 | 0.5秒 | 0〜5秒 |
| 最小発話長 | 0.1秒 | 0〜5秒 |

現在の実装では、前後の余裕のうち大きい値をVADの共通余裕として使用します。前後それぞれの設定値が、独立した境界として厳密に適用されるわけではありません。

### Haasの補助認識

必要な場合だけ、「音声処理」→「Haas 補助認識」を有効にします。モデル準備は次のコマンドです。

```powershell
pwsh -NoProfile -File .\scripts\Prepare-Speech.ps1 -IncludeHaas
```

準備後にGUIでも有効にする必要があります。認識文・時刻情報は記録に含まれますが、字幕やテキストファイルを別に書き出す機能はありません。認識が空だっただけで会話なしと決めません。処理負荷が高い場合はHaasを無効にして標準VADで使用できます。

### ノイズ除去

初期値は全枠「ノイズ除去なし」です。「デバイス」の枠ごとに、見つかったプラグインから1つを選択します。RNNoise・DeepFilterNet3・RE-USEに対応し、専用モデルがあればRE-USE laughterも候補になります。laughterは今回未配置です。

EXEと同じフォルダー以下へ `talkrecorder-plugin.json`・DLL・必要モデルを一緒に置き、停止中に「プラグインを再取得」を押します。不足した一式は候補に出しません。準備スクリプトの既定の配置先は `release/v0.1.0/plugins` にあります。配置・準備の詳細は[プラグイン説明](denoise-plugins.md)を参照してください。

配置や選択だけではDLLを動作させません。録音開始時に選択方式を読み込み、生成無音で動作・応答期限を確認してから機器の録音を始めます。入力確認では原音の波形だけを表示します。

ノイズ除去した音声を保存します。処理前の音声を別ファイルとして恒久保存する機能はありません。現在は区間単位の処理で、ステレオの左右を個別処理します。「RE-USEの処理単位」の初期値は5秒、有効範囲は0.05〜30秒です。他方式の内部フレーム長はこの値では変更しません。

開始前確認で応答期限を超えた場合は、軽い方式またはノイズ除去なしを選択してください。重なった会話ではRE-USEが主話者以外を抑える場合もあるため、小声や相槌を含め保存音声を確認します。

## 11. 詳細設定

普段は初期値のまま使用できます。次は「保存・時間」にあります。

| 項目 | 初期値 | 保存・開始時に有効な範囲・注意 |
| --- | ---: | --- |
| 分割間隔 | 600秒 | 0より大きく604,800秒以下 |
| 分割用の共通非発話 | 10秒 | 0より大きく604,800秒以下 |
| 非発話を残す長さ | 3秒 | 0〜604,800秒。設定値の半分が「処理待ちの上限」以下であること |
| 会話なし除外の判定 | 600秒 | 0より大きく604,800秒以下 |
| 処理待ちの上限 | 30秒 | 録音開始時1〜3,600秒 |
| 内部確定間隔 | 10秒 | 1〜60秒 |
| 再接続間隔 | 2秒 | 0.1〜60秒 |
| 音声解析の応答期限 | 10秒 | 0より大きく300秒以下 |
| 波形表示の時間 | 10秒 | 0より大きく600秒以下 |
| 未処理音声の上限 | 4,096MB | 16〜1,048,576MB。累積録音容量とは別 |
| 自動スリープ抑止 | ON | 録音中に有効。明示的なスリープや電源断は防げない |
| 起動時自動復旧 | ON | 起動時・録音開始前に、保存先内の未完了セッションを確認 |

秒数入力欄へ入れられる値と、設定として有効な範囲は項目によって異なります。保存・開始時にエラーになった場合は、この表の範囲を確認してください。

「FFmpeg」、音声処理のDLL・モデルのパスは、通常は準備スクリプトの配置先を使用します。相対パスは基準フォルダーから解決します。別の設定ファイルで起動した場合も、相対パスの基準がその設定ファイルの場所へ変わるわけではありません。

## 12. 切断や異常終了から復旧する

### デバイスが切断された

同じIDの機器へ自動再接続を試み、他の有効デバイスの録音は続けます。切断中に取得できなかった音声は復元できません。その時間を非発話として削除せず、全トラックの時間関係を維持します。

IDが変わった機器やチャンネル数が変わった機器へ、そのまま切り替えることはありません。復帰しない場合は停止し、接続先と機器選択を確認します。過去の取得形式を保存している機器なら、未接続のまま開始して再接続を待つこともできます。

### アプリやPCが異常終了した

1. 保存先のセッションフォルダーをそのまま残します。
2. 同じ保存先を指定した設定でアプリを起動します。
3. 「起動時自動復旧」が有効なら、未完了録音の確認終了を待ちます。
4. 通常の公開ファイルと、生成された `recovered` 内の音声一式・確定記録を確認します。

確定済みの内部音声と復旧可能な未確定末尾を処理します。繰り返し起動しても同じ範囲を二重出力しないように管理します。失敗した原音は残します。自動圧縮が有効なら、復旧したWAVもM4Aへの変換対象です。

### PCがスリープした

自動スリープ抑止が有効でも、利用者が明示したスリープや電源断は防げません。休止中の音声は録音できず、復帰後は新しいセッションとして再開します。休止時間を長い無音ファイルとして追加する仕組みではありません。

## 13. 困ったとき

| 症状 | 確認すること |
| --- | --- |
| 録音開始がエラーになる | 有効な枠に実際の機器を選んだか、重複指定がないか、保存先やモデル・FFmpegのパスが正しいかを確認 |
| 録音開始や設定保存が押せない | 録音準備・録音・停止後処理・起動時復旧が終了しているか確認 |
| マイクの波形が動かない | マイクの接続・ミュート・Windowsのマイク利用設定を確認し、停止後にデバイスを再取得 |
| RDPのマイクが見えない | 接続元のリモートオーディオ設定で、このコンピューターから録音する設定を確認。必要なら再接続後に機器を再取得 |
| スピーカーの波形が動かない | 実際の再生先と選択した出力デバイスが同じかを確認。再生していない場合は波形が平坦でも正常 |
| 波形は動くが発話表示が出ない | 入力確認は波形専用。本録音で確認する。録音中なら音声モデルと状態メッセージを確認 |
| 無音カットされない | 全有効デバイスが同時に非発話かを確認。1台でも発話・未判定ならカットしない |
| 10分でファイルが見えない | 既定では10分から10分10秒の間で区切る。画面下部で解析待ち、書き出し・検証の状態を確認。全区間が共通非発話で除外された場合はファイルを作成しない |
| 音声が小さくなった・変わった | ノイズ除去を使っている場合は、停止後に「ノイズ除去なし」で短い録音と比較 |
| WAVを選んだのにM4Aになる | WAVを残す場合は「WAV自動圧縮」をOFFにする |
| ノイズ除去の候補が出ない | EXE配下に定義・DLL・必要モデルが揃っているか確認し、「プラグインを再取得」を押す |
| プラグインの動作確認で停止する | 配置・依存DLL・処理負荷を確認。応答期限を超える方式は別方式かノイズ除去なしへ変更 |
| 文字起こしが表示されない | Haasは任意機能。画面上に認識文を表示する専用ビューや字幕出力はない |
| 処理待ちが増える | Haasやノイズ除去を使っている場合は、停止後に無効化して負荷を比較。解析失敗区間は判定不能として保持 |
| 画面がなくなった | 通知領域アイコンを左ダブルクリック、右クリック「設定を開く」、またはEXEを再実行。×は終了ではない |
| プロセスが複数見える | GUI本体と音声workerを区別。GUIは同じログオンセッションで1つ |
| 終了に時間がかかる | 録音の残りの解析・保存、復旧・圧縮の完了を待機。終了待ち中の強制停止は未完了データを残す場合がある |
| 保存エラー・容量不足 | 空きを確保し、元のセッションと未完了データを保持して復旧を試す。元WAVの変換には変換先の一時空きも必要 |
| 空き容量で自動停止した | 「停止する空き容量」の設定を確認。空きを確保してから再開。0指定なら容量による停止は無効 |

調査が必要な場合は、アプリ版、発生日時、画面のエラー文、該当セッションの `session.json`・`timeline.jsonl`・`capture-timing.jsonl` を確認します。録音音声やHaasの認識文には会話内容が含まれるため、共有する範囲を選んでください。
